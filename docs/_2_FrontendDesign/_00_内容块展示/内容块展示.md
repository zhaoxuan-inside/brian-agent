# Block-Native Chat/Agent 内容展示层前端 PRD

## 1. 项目概述
### 1.1 项目背景
当前 Chat LLM 及 Agent 产品的内容展示普遍采用单一的文本流或 Markdown 渲染模式，导致结构化信息（如工具调用、思维链、多模态结果）展示能力孱弱，无法有效区分信息层级与语义类型。本项目旨在构建一套独立于内容编排逻辑的纯展示引擎，借鉴 Notion Block 设计理念，将对话内容抽象为标准化数据块，实现内容数据与视觉展示的彻底解耦。

### 1.2 项目目标
-   建立标准化的 Block 数据消费契约，支持异构内容的统一接入。
-   实现高性能的流式 Block 解析与增量渲染，保障生成过程的流畅体验。
-   提供插件化的块渲染机制，支持内容类型的无限扩展而不侵入核心逻辑。
-   构建具备视觉层级、交互反馈与无障碍支持的只读展示界面。
-   确保在长对话、复杂嵌套等极端场景下的渲染性能与稳定性。

### 1.3 范围界定
-   **包含**：流式数据解析、Block 组装、虚拟化渲染、块级视觉交互（折叠/展开/复制等）、错误降级、响应式适配、主题支持。
-   **不包含**：用户消息发送、内容编辑、块拖拽排序、Slash Commands、数据持久化写入、权限控制、协作逻辑。

## 2. 数据消费契约需求
### 2.1 Block 数据结构
展示层需消费标准化的 Block 数据对象，每个对象必须包含全局唯一标识符、块类型标识、渲染所需的数据载荷以及展示专用元信息。

### 2.2 展示元信息规范
每个 Block 数据对象必须携带仅用于展示层的元信息字段，包括：
-   **流式状态**：标识当前块处于空闲、流式生成中、已完成或错误状态。
-   **视觉状态**：标识块的初始折叠/展开/最小化状态（可由用户本地覆盖）。
-   **错误信息**：当流式状态为错误时，提供用于展示的友好文案及原始错误码。
-   **进度指示**：针对长耗时任务块，提供 0-100 的数值型进度。
-   **时间戳**：可选字段，用于辅助展示生成时间。

### 2.3 数据更新协议
展示层需支持通过增量事件驱动视图更新，事件类型包括块插入、块内容追加、块属性更新、块移除。所有更新操作必须是幂等的，且未变更的块对象引用必须保持稳定以支持精准渲染。

## 3. 流式解析与组装需求
### 3.1 流解析器
系统需提供独立的流解析模块，负责将原始 SSE/WebSocket 事件流转换为标准 Block 操作指令。解析器必须是纯函数实现，不依赖任何 UI 框架，可独立进行单元测试。

### 3.2 缓冲与节流
对于高频更新的文本类块，解析器必须实现基于帧率的缓冲合并机制，避免每个 token 到达都触发视图重绘。非文本类的状态变更事件应绕过缓冲立即处理。

### 3.3 完整性保障
解析器必须具备超时检测与异常中断处理能力。当连接断开或未收到明确的结束信号时，必须自动将所有处于流式状态的块标记为完成或错误状态，防止界面永久停留在加载态。

### 3.4 数据校验与降级
解析器在组装 Block 数据时必须进行 Schema 校验。对于不符合契约的数据，必须生成标准的 Fallback Block 而非抛出异常，同时上报监控日志。

## 4. 渲染引擎需求
### 4.1 虚拟化渲染
展示列表必须采用虚拟化滚动技术，仅渲染视口内及预加载区域的块。系统需支持动态高度测量与缓存，避免因块高度不确定导致的布局抖动。

### 4.2 流式锚定
当最新块处于流式生成状态且用户视口位于底部阈值内时，列表必须自动跟随滚动。当用户主动上滑超出阈值后，自动跟随必须立即解除，直到用户手动回到底部。

### 4.3 块注册表
系统需提供插件化的块渲染器注册机制。每种块类型对应一个独立的渲染组件，通过类型标识符动态匹配。新增块类型仅需注册新组件，不得修改渲染引擎核心代码。

### 4.4 精准更新
渲染引擎必须确保单个块的内容或状态变更不会导致其他未变更块的重渲染。流式追加内容时，仅更新目标块的内部状态，不触发列表级的重新布局。

## 5. 内置块类型展示需求
### 5.1 文本段落块
-   支持富文本行内样式渲染。
-   流式生成时在末尾显示闪烁光标，完成后光标淡出。
-   文本内容必须支持原生选中与复制。

### 5.2 标题块
-   支持多级字阶与对应的上下留白规范。
-   点击标题需生成可分享的锚点链接。

### 5.3 代码块
-   支持语法高亮，高亮计算不得阻塞主线程。
-   流式生成时自动滚动至最新行。
-   提供一键复制功能与语言标签展示。
-   超长代码需提供降级渲染策略。

### 5.4 思维链块
-   默认以折叠态展示，仅显示摘要信息与时长。
-   折叠态下若内容仍在流式生成，需显示活动指示器。
-   展开/收起切换需具备平滑过渡动画。
-   展开后内容区域需自动滚动至可视区域。

### 5.5 工具调用块
-   以卡片形式展示工具名称、参数摘要与执行状态。
-   加载中状态显示骨架屏或加载动画。
-   完成后展示结果摘要，支持展开查看完整参数与返回值。
-   结果内容支持复制。

### 5.6 产物预览块
-   以带边框卡片展示标题与缩略图/摘要。
-   资源加载中显示占位符，加载完成后淡入展示。
-   点击触发外部预览回调（如打开侧边栏或全屏）。

### 5.7 错误块
-   以警示样式展示友好错误文案。
-   悬停时展示原始错误码与技术详情。
-   若上游提供重试回调，则展示重试按钮；否则仅展示信息。

### 5.8 兜底块
-   当遇到未注册的块类型或数据异常时渲染。
-   以虚线边框与明确标签提示“不支持的内容类型”。
-   开发环境下可切换展示原始 JSON 数据。

## 6. 交互与体验需求
### 6.1 块级悬浮工具栏
鼠标悬停于块区域一定延迟后，需在固定位置浮现轻量操作工具栏。鼠标移出后工具栏需延迟消失以避免误触。移动端需改为长按触发底部操作面板。

### 6.2 本地视觉状态管理
块的折叠/展开、详情展开等状态必须由独立的本地状态管理，不得与数据层混合。这些状态是临时的，页面刷新后可重置，无需持久化。

### 6.3 操作反馈
所有可交互元素（复制、折叠、重试等）在触发后必须提供即时的视觉反馈，如图标切换、Toast 提示或按钮状态变更。

### 6.4 键盘导航
所有可交互块元素必须支持 Tab 键聚焦与 Enter/Space 键触发操作。焦点样式必须清晰可见。

### 6.5 无障碍支持
-   流式生成中的文本块需声明 aria-live 属性。
-   折叠/展开元素需正确声明 aria-expanded 状态。
-   每个块需具备语义化的 ARIA role。
-   错误块需使用 alert role 确保屏幕阅读器即时播报。

## 7. 性能需求
### 7.1 渲染帧率
文本流式生成峰值期间，渲染帧率不得低于 55fps。千块规模下滚动帧率不得低于 58fps。

### 7.2 首屏性能
百块规模下首次内容绘制时间不得超过 800ms。

### 7.3 布局稳定性
流式生成期间的累积布局偏移值不得超过 0.05。

### 7.4 内存控制
两千块规模下内存占用不得超过 150MB。

### 7.5 降级可靠性
未知块类型或异常数据的降级渲染成功率必须达到 100%，严禁白屏或崩溃。

## 8. 兼容性与适配需求
### 8.1 响应式布局
展示引擎需适配桌面端与移动端。移动端需针对触摸操作、横向溢出、工具栏触发方式做专项适配。

### 8.2 主题支持
所有视觉样式必须通过 CSS 变量或等效机制驱动，支持运行时主题切换且不引发额外重绘。

### 8.3 浏览器兼容
需支持主流现代浏览器的最新两个大版本。对于不支持的特性需提供优雅降级方案。

## 9. 交付物需求
-   标准化 Block 数据类型定义包。
-   可独立测试的纯函数流解析器。
-   内置块渲染组件库。
-   整合虚拟化与状态管理的展示容器组件。
-   覆盖所有内置块类型静态与流式模拟的组件文档。
-   性能监控仪表盘集成方案。
