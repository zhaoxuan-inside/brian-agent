# 配置页面产品需求文档 (PRD)

## 1. 文档概述

### 1.1 产品背景

Brian-Agent 是一个多层 DDD 架构的 Agent 系统，具备 LLM 调用、记忆管理、多 Agent 协作、任务编排、自学习进化等能力。当前配置页面仅零散覆盖了 LLM Provider/Model、Soul、Skill、MCP 等少数模块的实体 CRUD，大量核心运行参数散落在各层模块的内部配置表中，无法被统一管理，远未达到"系统配置中心"的要求。

### 1.2 设计原则

- **按功能域聚合**：配置项按 Agent 系统的功能域（LLM、Agent、记忆、工具、编排等）组织，而非机械照搬代码分层。
- **配置项跟随实体**：归属某个实体的配置（如 Provider 的配额、Agent 的优化规则）应放在该实体的管理界面中，不作为独立配置项散落。
- **实体管理与参数配置并存**：有的配置是"创建/修改一个实体"（如新增一个 LLM Provider），有的是"调整一个运行参数"（如修改 context 构建的 timeline 数量），两者交互模式不同但同属一个功能域。

### 1.3 配置组织总览

```
Agent 系统配置中心
├── 1. LLM 配置            ← 提供商、模型、配额、匹配策略
├── 2. Agent 配置          ← Agent 库、策略、构建、执行、上下文、进化
├── 3. 记忆与信息配置      ← 标签、摘要、向量化、上下文构建、老化清理
├── 4. 工具与技能配置      ← Skill、MCP、工具匹配与优化
├── 5. 角色与提示词配置    ← Soul、Prompt Template
├── 6. 编排配置            ← 入口、策略、执行、可视化
├── 7. 基础设施配置        ← 日志、消息队列、存储后端
└── 8. 应用配置            ← 对话、自学习、用户画像、可视化应用
```

## 2. LLM 配置

LLM 是 Agent 系统的核心能力。配置包括：管理可用的 LLM 提供商和模型、设置调用配额、控制模型匹配策略。

### 2.1 实体管理

#### 2.1.1 LLM Provider（提供商）

Provider 代表一个 LLM 服务端点。用户可按需新增，删除，修改，搜索，启用/禁用模型提供商。

**字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `llm_provider_id` | UUID | 是 | 提供商ID |
| `llm_provider_title` | String | 是 | 提供商名称（如 OpenAI、DeepSeek） |
| `llm_provider_url` | URL | 是 | API 端点地址 |
| `llm_provider_brief` | Text | 否 | 描述说明 |
| `get_models_path` | Text | 否 | 获取模型列表接口 |
| `api_key` | Secret | 否 | API 密钥（脱敏存储和显示） |
| `enable` | Boolean | — | 启用/停用 |

**每 Provider 的配额设置**：

| 配额项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 每日 Token 限额 | INT | 0 | 0 = 不限制 |
| 每周 Token 限额 | INT | 0 | 0 = 不限制 |
| 每月 Token 限额 | INT | 0 | 0 = 不限制 |
| 每日调用次数限额 | INT | 0 | 0 = 不限制 |
| 每周调用次数限额 | INT | 0 | 0 = 不限制 |
| 每月调用次数限额 | INT | 0 | 0 = 不限制 |

> **设计要点**：配额是 Provider 的属性，在 Provider 详情中配置，而非作为独立配置项平铺在列表中。

**操作**：新建 Provider、编辑、删除、启停、连接测试。

#### 2.1.2 LLM Model（模型）

每个 Provider 下可配置多个 Model。系统预置各 Provider 的常见模型（如 gpt-4o、claude-3-5-sonnet），用户可自定义添加。

**字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `llm_provider_id` | Ref | 是 | 所属 Provider |
| `llm_title` | String | 是 | 模型名称（如 gpt-4o） |
| `llm_brief` | Text | 否 | 模型描述 |
| `llm_usage` | Enum | 否 | 用途类型：text（文本生成）/ vision（多模态）/ embedding（向量化） |
| `enable` | Boolean | — | 启用/停用 |

**操作**：新建 Model、编辑、删除、启停、设为系统默认、连接测试。

### 2.2 运行参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 全局每日 Token 限额 | INT | 0 | 所有 Provider 合计的每日 Token 上限（0=不限，与 Provider 级限额取较严者） |
| 全局每周 Token 限额 | INT | 0 | 同上 |
| 全局每月 Token 限额 | INT | 0 | 同上 |
| 全局每日调用次数限额 | INT | 0 | 同上 |
| 全局每周调用次数限额 | INT | 0 | 同上 |
| 全局每月调用次数限额 | INT | 0 | 同上 |
| 模型重新匹配概率 | INT | 75 | 0-100，值越大系统越倾向于重新评估当前任务应使用哪个模型 |
| 匹配排名 Prompt 模板 | Ref | — | 用于 LLM 匹配排名的 Prompt 模板 |

## 3. Agent 配置

Agent 层管理 Agent 实例的创建、策略选择、上下文构建、执行控制与持续进化。

### 3.1 Agent 实例库

Agent 实例是系统中执行任务的工作单元。每个 Agent 绑定了策略、LLM、Soul，通过任务签名进行匹配复用。

**Agent 实体字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_name` | String | 是 | Agent 名称 |
| `agent_type` | Enum | 是 | 类型：WORKER（工作Agent）/ PLANNER（规划Agent）/ WRITER（写作Agent）/ EVOLUTOR（进化Agent） |
| `strategy_id` | Ref | 是 | 绑定的执行策略 |
| `llm_id` | Ref | 是 | 绑定的 LLM 模型 |
| `soul_id` | Ref | 否 | 绑定的人格 Soul |
| `task_signature` | Text | 是 | 任务签名（用于匹配相似任务复用 Agent） |
| `enable` | Boolean | — | 启用/停用 |
| `eval_score` | Float | 只读 | 评估分数（系统自动更新） |
| `usage_count` | Int | 只读 | 使用次数（系统自动更新） |

**匹配参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 匹配相似度阈值 | DOUBLE | 0.7 | 任务签名相似度超过此值的 Agent 被匹配 |
| 匹配 Prompt 模板 | Ref | — | Agent 匹配排名的 Prompt 模板 |
| 最大 Agent 数量 | INT | 100 | 系统中 Agent 实例上限 |

**优化与淘汰规则**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 观察天数 | INT | 30 | 统计窗口 |
| 最小使用次数 | INT | 5 | 窗口内使用次数低于此值的 Agent 可能被淘汰 |
| 最小评估分数 | DOUBLE | 0.5 | 评估分数低于此值的 Agent 可能被淘汰 |

### 3.2 执行策略

策略定义了 Agent 执行任务的方式。系统内置 3 个策略：

| 策略名称 | 适用复杂度 | 最大迭代 | 适用场景 |
|----------|-----------|----------|----------|
| CoT（Chain-of-Thought） | 0–40 | 1 | 简单任务，单步推理直接回答 |
| ReAct（Reasoning+Acting） | 30–70 | 10 | 中等任务，思考→行动→观察循环 |
| Plan-and-Solve | 60–100 | 20 | 复杂任务，先制定计划再逐步执行 |

**策略实体字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `strategy_label` | String | 策略名称 |
| `suitable_complexity_min` | Int | 适用复杂度下限 0-100 |
| `suitable_complexity_max` | Int | 适用复杂度上限 0-100 |
| `suitable_domains` | JSON | 适用领域列表 |
| `execution_rule` | JSON | 执行规则（最大迭代次数等） |
| `enable` | Boolean | 启用/停用 |

**操作**：新建策略、编辑、删除（内置 3 个策略不可删除）、启停。

**策略选择参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 默认策略 ID | Ref | — | 无匹配策略时的兜底策略 |
| 策略匹配 Prompt 模板 | Ref | — | 用于策略选择的 Prompt 模板 |

### 3.3 Agent 构建

Agent 构建器负责根据任务自动分析并组装 Agent。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 任务分析 Prompt 模板 | Ref | — | 分析任务特征所用的 Prompt 模板 |
| 新建 Agent 默认策略 | Ref | — | 自动构建时赋予 Agent 的默认策略 |
| 自动优化构建 | BOOLEAN | false | 是否在使用中自动优化 Agent 组装 |

### 3.4 Agent 执行

控制 Agent 运行时的行为参数。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 思考阶段 Prompt 模板 | Ref | — | Think 阶段 Prompt |
| 反思阶段 Prompt 模板 | Ref | — | Reflect 阶段 Prompt |
| 回答阶段 Prompt 模板 | Ref | — | Answer 阶段 Prompt |
| 默认最大迭代次数 | INT | 3 | 单次 Agent 执行的最大思考-行动循环数 |
| 异步 Worker 轮询间隔 | INT | 1000 | 毫秒 |

### 3.5 Agent 上下文

控制为 Agent 构建上下文时的行为。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 最大上下文条目数 | INT | 200 | 注入 Agent 的上下文信息条数上限 |
| 持久化上下文快照 | BOOLEAN | true | 是否保存上下文快照到数据库 |

### 3.6 专用 Agent 配置

#### Planner Agent（规划）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 复杂度分解阈值 | INT | 50 | 任务复杂度超过此值时触发分解为子任务 |
| 计划生成 Prompt 模板 | Ref | — | Prompt 模板 |
| 最大子任务数 | INT | 10 | 单次规划最多生成多少个子任务 |

#### Writer Agent（写作）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 写作 Prompt 模板 | Ref | — | Prompt 模板 |
| 默认输出语言 | ENUM | zh-CN | zh-CN / en / ja 等 |
| 默认写作风格 | ENUM | clear | clear / academic / creative / concise / professional |
| 默认内容深度 | ENUM | medium | brief / medium / detailed |
| 默认输出格式 | ENUM | MARKDOWN | MARKDOWN / PLAIN / HTML |

#### Evolutor Agent（进化）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| Work 评估 Prompt 模板 | Ref | — | 评估 Work 执行质量 |
| 写作评估 Prompt 模板 | Ref | — | 评估写作输出质量 |
| 触发优化阈值 | DOUBLE | 0.7 | 评估分数低于此值时触发优化 |
| 评估频率阈值 | INT | 10 | 每 N 次 Agent 调用触发一次评估 |
| 定时评估间隔 | INT | 3600000 | 毫秒，默认 1 小时 |
| 评估批处理大小 | INT | 5 | 每批评估多少条记录 |

> **注**：Agent 层配置项当前未注册到全局 `config_registry` 表。前端实现需配合后端完成注册。

## 4. 记忆与信息配置

Agent 的记忆系统负责存储、索引、检索对话信息，通过标签、摘要、向量化、关键词等多维度组织上下文。

### 4.1 信息存储

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 信息保留最大天数 | INT | 30 | 超过此天数的信息将被自动清理 |

### 4.2 标签生成

自动为信息生成标签，用于分类与关联检索。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用标签生成 | BOOLEAN | false | 是否自动生成标签 |
| 标签生成 LLM | Ref | — | 执行标签生成所用的 LLM 模型 |
| 标签生成 Prompt 模板 | Ref | — | Prompt 模板 |
| 标签 Top-K 数量 | INT | 5 | 每条信息生成几个标签 |

### 4.3 摘要生成

自动为信息生成摘要。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用摘要生成 | BOOLEAN | false | 是否自动生成摘要 |
| 摘要生成 LLM | Ref | — | LLM 模型 |
| 摘要生成 Prompt 模板 | Ref | — | Prompt 模板 |

### 4.4 向量化

将信息向量化以支持语义相似度检索。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用向量化 | BOOLEAN | false | 是否自动执行向量化 |
| 向量化 LLM | Ref | — | Embedding 模型 |
| 向量维度 | INT | 1024 | 向量维度数 |

### 4.5 Agent 上下文构建

当 Agent 执行任务时，从记忆系统中检索相关信息构建上下文。以下参数控制各类信息的检索数量。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 时间线基础数量 | INT | 500 | 从时间线中取最近 N 条信息 |
| 标签关联基础数量 | INT | 200 | 从标签关联图中取 N 条相关信息 |
| 相似度基础数量 | INT | 150 | 从向量相似度检索中取 N 条 |
| 关键词基础数量 | INT | 100 | 从关键词检索中取 N 条 |
| 随机采样基础数量 | INT | 50 | 随机采样 N 条（增加多样性） |
| 上下文总数上限 | INT | 1000 | 所有来源合计不超过此值 |

> **注意事项**：五项基础数量之和超过 `总数上限` 时系统会按比例缩减。这些参数直接影响 Agent 的"记忆范围"——值越大 Agent 能参考的信息越多，但也会增加 Token 消耗和响应延迟。

## 5. 工具与技能配置

Agent 通过 Skill（自定义技能脚本）和 MCP（Model Context Protocol 外部工具）扩展能力。

### 5.1 Skill（技能）

Skill 是在沙箱中执行的 JavaScript 代码片段，Agent 可以调用 Skill 完成特定任务。

**Skill 实体字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `skill_brief` | Text | 是 | 技能描述（用于 Agent 匹配） |
| `work` | Code (JS) | 是 | 执行代码（Node.js vm 沙箱运行） |
| `scripts` | JSON | 否 | 附加脚本 |
| `references` | JSON | 否 | 参考资料 |
| `assets` | JSON | 否 | 静态资源 |
| `enable` | Boolean | — | 启用/停用 |

**操作**：新建 Skill、编辑、删除、启停、沙箱测试执行。

### 5.2 MCP（外部工具服务）

两层管理：MCP Provider（工具市场注册源）+ MCP Instance（已安装的工具实例）。

**MCP Provider 字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `mcp_provider_title` | String | 提供商名称 |
| `mcp_provider_url` | URL | API 端点 |
| `mcp_provider_brief` | Text | 描述 |
| `enable` | Boolean | 启用/停用 |

系统预置 6 个公共 MCP 注册源模板（MCP Registry、MCP Hub、MCP Market 等）。

**MCP Instance 字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `mcp_provider_id` | Ref | 来源 Provider |
| `mcp_title` | String | 工具名称 |
| `mcp_brief` | Text | 工具描述 |
| `mcp_install_cmd` | String | 安装命令 |
| `mcp_start_cmd` | String | 启动命令 |
| `mcp_stop_cmd` | String | 停止命令 |
| `mcp_uninstall_cmd` | String | 卸载命令 |
| `enable` | Boolean | 启用/停用 |

**操作**：Provider 的新建/编辑/删除/启停/连接测试；Instance 的安装/卸载/启动/停止/启停。

**MCP 配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| MCP 缓存 TTL | INT | 86400 | MCP 列表缓存时间（秒，默认 1 天） |

### 5.3 工具匹配与优化

控制 Agent 如何选择使用哪个 Skill 或 MCP。

| 参数 | 适用 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| 重新匹配概率 | Skill | INT | 75 | 0-100，值越大越倾向于重新评估 Skill 选择 |
| 匹配排名 Prompt 模板 | Skill | Ref | — | Prompt 模板 |
| 重新匹配概率 | MCP | INT | 75 | 同上，针对 MCP |
| 匹配排名 Prompt 模板 | MCP | Ref | — | Prompt 模板 |

**优化与淘汰规则**（Skill/Soul 共用模式）：

| 参数 | 适用 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| 观察天数 | Skill | INT | 30 | 统计窗口 |
| 最小使用次数 | Skill | INT | 5 | 低于此使用次数的技能可能被淘汰 |
| 观察天数 | Soul | INT | 30 | 同上，针对 Soul |
| 最小使用次数 | Soul | INT | 5 | 同上 |

## 6. 角色与提示词配置

### 6.1 Soul（人格角色）

Soul 定义 Agent 的人格特征、行为风格和角色设定。

| 字段 | 类型 | 必填 | 说明 |

**操作**：新建 Soul、编辑、删除、启停。

**Soul 匹配参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|

| 匹配排名 Prompt 模板 | Ref | — | Prompt 模板 |

### 6.2 Prompt Template（提示词模板）

**Prompt 实体字段**：

| 字段 | 类型 | 必填 | 说明 |

| `enable` | Boolean | — | 启用/停用 |

**操作**：新建模板、编辑、删除、启停、预览渲染（填入变量后查看实际输出）。

## 7. 编排配置

Orchestration 层负责将用户请求分解为任务、选择执行策略、调度 Agent 执行并汇总结果。

### 7.1 编排入口

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 复杂度分解阈值 | INT | 50 | 任务复杂度超过此值时触发分解为子任务 |
| 默认编排策略 | ENUM | SIMPLE | SIMPLE（单Agent直接执行）/ COMPLEX（多Agent协作） / DAG（有向无环图调度） |
| 策略选择 Prompt 模板 | Ref | — | Prompt 模板 |
| 最近 Work 引用数 | INT | 5 | 构建上下文时引用最近 N 个 Work |
| 异步 Work 轮询间隔 | INT | 1000 | 毫秒 |

### 7.2 编排策略

管理编排工作流的策略定义。

**Strategy 实体字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `strategy_label` | String | 策略名称 |
| `strategy_description` | Text | 策略描述 |

## 10. 配置分类与交互模式

### 10.1 实体管理 vs 参数配置

| 交互模式 | 适用场景 | 界面形态 |
|----------|----------|----------|
| **实体管理** | LLM Provider/Model、Soul、Skill、MCP Provider/Instance、Prompt Template、Agent、Strategy、Orchestration Strategy | 表格列表 + 新建/编辑弹窗，支持启停、测试连接、安装/卸载等操作 |
| **参数配置** | 上述各功能域的运行参数 | 分类分组 + 配置项列表，支持原地编辑（Switch/Input/Select）或 JSON 编辑器 |

### 10.2 引用类型配置项的处理

配置项中类型为 `Ref`（引用其他实体 ID）的参数——如 "标签生成 LLM"、"匹配排名 Prompt 模板"——**前端应渲染为下拉选择器**，数据源来自对应实体列表（已启用的 LLM Model 列表、已启用的 Prompt Template 列表等），而非自由文本输入。

### 10.3 关联实体展示

部分模块的实体之间存在关联，在详情页应展示关联信息：

- LLM Provider 详情 → 列出其下所有 Model，支持直接在此新建 Model
- Agent 详情 → 展示其绑定的 Strategy、LLM、Soul 名称及状态
- Skill 详情 → 展示被哪些 Agent 引用
- MCP Provider 详情 → 列出已安装的 MCP Instance

## 13. 非功能性需求

- **性能**：全量配置加载 < 2s；单个配置保存响应 < 500ms；连接测试超时 10s。
- **安全**：API Key 类字段脱敏展示（`sk-****abcd`），点击可短暂查看；关键配置变更需确认。
- **无障碍**：WCAG AA 级别，键盘完全可操作。
- **兼容性**：Chrome/Edge/Firefox/Safari 最新两个主版本，最小宽度 375px。
- **数据一致性**：配置修改后独立路由页面（/models、/souls 等）即时同步。
