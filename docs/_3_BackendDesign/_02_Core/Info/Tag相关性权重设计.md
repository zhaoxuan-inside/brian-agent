# Tag相关性权重设计

## 一、数据模型与属性定义

### 1.1 节点类型（实体）

| 类型 | URI 模板 | 索引要求 |
| :--- | :--- | :--- |
| 内容节点 | `ex:Content/{id}` | 需在 `ex:contentId` 上建立哈希索引 |
| 标签节点 | `ex:Tag/{id}` | 需在 `ex:tagId` 上建立哈希索引 |

### 1.2 边类型（谓词）与属性存储结构

采用 RDF*（或命名图）方式将属性挂载在边上。所有数值属性使用 `xsd:double` 或 `xsd:string`（仅 Map 字段）。

| 谓词（边类型） | 源节点 → 目标节点 | 挂载属性（键 → 数据类型） | 存储策略 |
| :--- | :--- | :--- | :--- |
| `ex:similarTo` | `ex:Tag` → `ex:Tag` | ① `ex:similarity` → `xsd:double`<br>② `ex:actMap` → `xsd:string`（JSON 对象） | 静态相似度（只读）、动态激活图 |
| `ex:hasTag` | `ex:Content` → `ex:Tag` | 无属性（仅用于反向查内容） | 普通边，无额外负载 |

**`ex:actMap` 的 JSON 字符串格式规范**：

```json
{"2026-07-20": 5, "2026-07-21": 3, "2026-07-22": 8}
```

- Key：`xsd:date` 格式（`YYYY-MM-DD`），表示激活发生的自然日。
- Value：`xsd:integer`，表示该自然日内该边被激活的总次数。
- **强制约束**：Map 中最多保留最近 $N_{max} = 60$ 个键值对，超期数据需通过异步任务裁剪。

## 二、核心权重计算公式体系

### 2.1 基于日期 Map 的动态活跃度 $A_{vw}$

对于边 $e = (v, w)$，给定当前计算基准日期 $D_{now}$，其历史激活数据为集合 $\mathcal{H} = \{(D_i, c_i)\}$，其中 $c_i$ 为当天的激活次数，$d_i = D_{now} - D_i$ 为相隔天数（单位：天）。活跃度指标采用**反比例衰减加权**与**总量对数补偿**的双因子融合：

$$
A_{vw}(D_{now}) = \sum_{(D_i, c_i) \in \mathcal{H}, \, 0 \le d_i < N_{max}} \left( \frac{c_i}{\alpha \cdot d_i + 1} \right) + \beta \cdot \ln\left(1 + \sum_{(D_i, c_i) \in \mathcal{H}} c_i \right)
$$

| 参数 | 配置项 | 推荐值 | 设计意图 |
| :--- | :--- | :--- | :--- |
| $\alpha$ | `decay_slope` | **0.06** | 控制历史日期的衰减斜率，30 天前单日权重衰减至 $1 / (0.06 \times 30 + 1) \approx 35.7\%$，避免指数衰减导致的“归零”现象。 |
| $\beta$ | `total_bonus` | **0.4** | 对总累积次数取对数补偿，确保长期低频活跃边不会被近期高频边完全压制，保留基础竞争力。 |
| $N_{max}$ | `retention_days` | **60** | 滑动窗口长度，查询时仅遍历窗口内的 Map 键，超过该天数的数据在计算中权重为 0 且标记为待清除。 |

---

### 2.2 单条 Tag→Tag 边的实时路径权重 $W(e)$

当从起始内容提取的起始 Tag $v$ 出发，经过 $k$ 跳到达目标内容关联的 Tag $w$ 时（$k \ge 1$），该条有向通路的边权重定义为：

$$
W(e) = s_{vw} \cdot \left( \gamma \right)^{k-1} \cdot \log_2\left(2 + A_{vw}(D_{now}) \right)
$$

| 符号 | 来源/配置 | 说明 |
| :--- | :--- | :--- |
| $s_{vw}$ | 边属性 `ex:similarity` | 预计算的静态 Jaccard/Cosine 相似度，归一化至 $[0, 1]$。 |
| $\gamma$ | `hop_decay_factor` | 跳数衰减基数，配置 **0.80**。每增加一跳，权重乘以 0.8，3 跳时权重为 $0.8^2 = 0.64$ 倍。 |
| $k$ | 查询时实时计算 | 从初始 `ex:Tag` 到目标 `ex:Tag` 在图中的最短路径跳数，最大限制为 3。 |
| $\log_2(2 + A)$ | 对数压缩函数 | 当 $A=0$ 时值为 1，确保无历史激活的边仅凭相似度参与排序；压缩高活跃度边的数值膨胀，维持相似度的决策占比。 |

---

### 2.3 目标内容的最终多路径加权得分 $\text{FinalScore}(C)$

设同一目标内容节点 $C$ 通过 $M$ 条不同的 Tag 通路被检索到，则聚合公式为：

$$
\text{FinalScore}(C) = \sum_{p=1}^{M} \left[ W(e_p) \cdot \phi(\text{deg}(v_p)) \cdot \rho_p \right]
$$

**额外惩罚项配置**：

| 惩罚因子 | 公式 | 配置值/含义 |
| :--- | :--- | :--- |
| 度数惩罚 $\phi(\text{deg})$ | $\displaystyle \phi(\text{deg}) = \frac{1}{\log_2(\text{deg} + 1)}$ | 惩罚连接数（$\text{deg}$）过高的泛化 Tag，防止超级节点主导结果。 |
| 日期分布一致性 $\rho_p$ | $\displaystyle \rho_p = \frac{1}{1 + \sigma(\mathcal{D}_p)}$ | $\mathcal{D}_p$ 为边 `actMap` 中所有有激活记录的日期集合（转换为天数序列），$\sigma$ 为标准差。激活日期越集中在某几天，标准差越小，$\rho \approx 1$；分布越离散，适当降权。 |

> **最终排序**：按 $\text{FinalScore}(C)$ 降序返回 Top-N 内容。

## 三、GraphDB 物理存储与索引设计

### 3.1 谓词索引配置

在 GraphDB 的 `repository-config.ttl` 中，针对高频过滤与排序属性启用**谓词索引**：

| 谓词 | 索引类型 | 说明 |
| :--- | :--- | :--- |
| `ex:similarity` | `SPI`（数值范围索引） | 支持相似度范围过滤和排序，用于快速定位“相似度最高”的边。 |
| `ex:tagId` / `ex:contentId` | `PREFIX` + `HASH` | 确保通过 ID 定位节点为 $O(1)$ 复杂度。 |
| `ex:hasTag` | `POS`（默认索引） | 反向查询（由 Tag 找 Content）依赖该索引，无需额外配置。 |

### 3.2 数据序列化与解析策略

- `ex:actMap` 存储为 `xsd:string` 字面量，不开启 GraphDB 内部的 JSON 索引（避免额外算力开销）。
- **解析责任**：由应用层（Node.js）在写入时序列化，查询时反序列化。查询返回边属性时，GraphDB 只负责传递字符串，不承担解析计算，最大限度释放数据库算力。

### 3.3 查询超时与内存保护

| 配置项 | 推荐值 | 说明 |
| :--- | :--- | :--- |
| `query-timeout` | **800 ms** | 单次 SPARQL 查询超时阈值，超时后引擎自动终止并返回已聚合的中间结果。 |
| `query-limit-results` | **10000** | 限制中间结果集的笛卡尔积上限，禁止查询引擎展开全图扫描。 |

## 四、候选路径采样与剪枝策略（最大 4 条通路）

为了严格将参与最终聚合计算 $M$ 的路径数量控制在 **$\le 4$**，同时保留探索性，采用如下确定性 + 随机性混合配置：

| 优先级 | 路径来源 | 选取规则 | 数量配额 |
| :--- | :--- | :--- | :--- |
| **1（确定性）** | 相似度最优 | 从起始 Tag 出发，限制 $k \le 2$，选取 `ex:similarity` 数值最高的唯一边。 | 1 条 |
| **2（探索性随机）** | 均匀随机抽样 | 剔除已选边后，从邻域池（$k \le 3$）中依据**均匀分布**随机抽取。若候选池不足则取实际数量。 | 3 条 |

**剪枝硬约束（熔断机制）**：

- 当遍历至任一 Tag 节点时，若其 `ex:similarTo` 出度 > $\theta = 500$，则触发扇出熔断，仅读取该节点邻接表中随机 500 条边用于上述采样，不对全表展开。
- 若查询执行时间超过全局 `query-timeout`（800ms），立即终止随机采样步骤，仅以已完成的确定性边（至少 1 条）返回结果。

## 五、系统级降级与容灾配置

| 负载等级 | 触发条件 | 执行策略 |
| :--- | :--- | :--- |
| **L1 轻度降级** | 平均响应时间 > 1.2s | 禁用“动态补偿”路径（第 3 优先级的 1 条），仅计算相似度最优 + 2 条随机边（最多 3 条）。 |
| **L2 重度降级** | CPU 利用率 > 85% 或查询超时率 > 15% | 彻底关闭随机采样，仅返回第 1 优先级的相似度最优边对应的内容。同时，公式 2.1 中的对数补偿项 $\beta \cdot \ln(\cdot)$ 置为 0，仅计算反比例衰减加权和，减少浮点运算量。 |
| **L3 故障旁路** | GraphDB 节点不可用 | 应用层直接从本地缓存（Redis）读取预先计算的 Top-20 热门内容兜底，缓存有效期 5 分钟。 |
