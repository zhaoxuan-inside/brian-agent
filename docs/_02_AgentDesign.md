# 1. 整体架构分层说明（从基础层到接入层）

| 层级 | 层名称 | 核心功能 |
| :--- | :--- | :--- |
| **第5层** | **应用层 (Application)** | 封装Agent的应用，依赖下层提供 Agent 能力，封装为一些抽象的能力，例如为上层的接入层提供问答能力，系统内部的学习能力等 |
| **第4层** | **编排层 (Orchestration)** | 接收上层的Agent能力请求，进行对请求进行分解、规划和编排，将复杂任务拆解为可以完成原子工作并派发给具体的 Agent 执行。 |
| **第3层** | **Agent层 (Agent)** | 负责 Agent 的管理，选择（根据工作内容选择目前可用的Agent）、新建（没有现成的Agent，根据工作内容，选择Skill，MCP，Soul封装可以完成工作的 Agent、删除（用户主动删除、支持不常用Agent自动老化）、复制更新（支持在现有Agent的基础上进行复制并进行优化）、调用（使用选择的Agent完成具体的工作） |
| **第2层** | **基础层 (Core)** | 负责管理基础组件，组件包括LLM，Soul，Skill，MCP（完成一项工作的工作流程或者落地方案），Info（用户的历史对话，学习到的信息） |
| **第1层** | **基础构件层 (Base)** | 负责抽象外部的功能，给上层提供能力 |

---

# 2. 各层详细说明

## 2.1. 第1层：基础构件层 (Base)
**功能描述**：  
该层负责**构建**和**管理**所有**基础能力**，通过对不同底层技术、模型和工具的封装，为上层提供统一、可替换的接口。

**组件说明**

| 组件名称 | 组件的构成/职责 |
| :--- | :--- |
| **LlmProvider** | 负责管理LLM模型提供商；管理LLM模型提供商提供的模型的管理；以及模型调用能力 |
| **PromptsProvider** | 负责管理 Prompt 模板，提供动态地构建Prompt的能力 |
| **MCPProvider** | 负责 MCP 提供商的管理，访问；提供MCP管理以及调用能力 |
| **SoulProvider** | 负责对Soul管理以及调用能力 |
| **SkillProvider** | 负责对Skill管理以及调用能力 |
| **StrategyProvider** | 负责对策略进行分层管理，策略为json格式，支持策略执行框架加载策略并应用策略进行执行 |
| **RelationDBProvider** | 对关系型数据库的封装，解耦上层业务和底层关系数据库；目前底层的关系数据库选择SQLite） |
| **GraphDBProvider** | 对图数据库的封装，解耦上层业务和底层图数据库；目前底层的关系数据库选择TinyGraphDB） |
| **MQProvider** | 对消息队列的封装，解耦上层业务和消息队列；目前通过 SQLite 实现消息队列功能。 |
| **VectorDBProvider** | 对向量数据库的封装，解耦上层业务和向量数据库；为上层进行向量存储和相似性检索能力；目前向量数据库选择 VectorDB |

---

## 2.2. 第2层：基础层 (Core)
**功能描述**：  
基于 Base 层的能力构建 Agent 底层能力组件；

**构成组件及说明**：

| 组件名称 | 组件的构成/职责 |
| :--- | :--- |
| **LLM** | 根据具体的工作选择 LLM ，调用 Prompts 封装器完成Prompt的构建 |
| **MCP** | 根据具体的工作选择 MCP，调用 Base 层的MCP 封装器完成MCP调用 |
| **Skill** | 根据具体的工作选择 Skill，调用 Base 层的 SKill 封装器完成 Skill 调用 |
| **Soul** | 根据具体的工作选择 Soul，Soul是某一类工作完成应该具有的品质或人格 |
| **思考策略** | 根据具体的工作选择具体的策略，指导 Agent 思考过程的模式，例如：CoT，ReACT等（默认）。 |
| **Info** | 用户的各种类型的信息的抽象，基于Base层的各种能力负责这些信息的管理；信息包括用户的历史对话，系统自学习到的信息； |

---

## 2.3. 第3层：Agent层 (Agent)
**功能描述**： 
Agent 执行框架，根据具体的工作选在可用的Agent或者基于Core层的所有组件构建完整的Agent，并完成工作； 
注意：Agent是完成一项工作的最基本单位；

---

## 2.4. 第4层：编排层 (Orchestration)
**功能描述**：  
Agent 编排框架，根据具体的工作，进行工作拆解编排为DAG图，基于将拆解后的子工作利用 Agent 层的能力，将子任务DAG图转成完成子任务的Agent DAG图，完成DAG 图的执行得到最终的回答；

---

## 2.5. 第5层：应用层 (Application)
**功能描述**：  
将底层的能力抽象为可以交付给用户的完整应用能力，屏蔽底层的复杂逻辑

**自带的构成组件及说明**：

| 组件名称 | 组件的构成/职责 |
| :--- | :--- |
| **SelfLearning** | 根据自学习策略，采集、规划和管理要学习的内容，驱动系统进行自我迭代和知识更新。 |
| **Chat** | 接受来自用户的 Chat 请求，是系统最核心的交互方式。 |
| **UserProfile** | 对用户的使用历史进行分析，分析用户的喜好，从而优化对用户输入的理解和对输出结果的指导。 |
| **Gateway** | 支持 IM（即时通讯）接入的网关，允许用户通过 IM 工具与系统交互。 |
